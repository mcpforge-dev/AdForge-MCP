# OpenHands для разработки HolyMedia MCP

OpenHands можно использовать как дополнительного инженерного AI-агента для разработки HolyMedia MCP. Это не клиентский MCP-подключатель и не часть публичного dashboard. Это инструмент для команды разработки: он помогает читать код, править файлы, запускать команды, писать тесты, проверять ошибки и готовить изменения.

## Что он делает

OpenHands работает как автономный coding agent:

- открывает репозиторий и понимает контекст проекта через `AGENTS.md`;
- может менять код и документацию;
- запускает тесты, линтеры, smoke-проверки и команды сборки;
- помогает разбирать баги, ошибки деплоя и регрессии;
- может готовить небольшие PR/commit-пакеты;
- подходит для повторяющихся задач: проверки, обновления документации, ревью, диагностики.

## Чем поможет HolyMedia MCP

Полезные сценарии для нашего проекта:

- быстро проверять UI/dashboard после задач;
- искать причины ошибок OAuth, MCP auth, user isolation и provider API;
- дописывать тесты на новые баги;
- проверять, что `/mcp` не открыт публично;
- делать security/error review перед деплоем;
- готовить изменения по документации для клиентов и специалистов;
- выполнять рутинные проверки перед commit/deploy.

## Безопасный режим для проекта

В репозиторий добавлены:

- `AGENTS.md` - постоянные инструкции для любого coding agent;
- `.openhands/setup.sh` - подготовка sandbox/workspace при запуске OpenHands;
- этот документ - инструкция для команды.

Главные ограничения:

- не коммитить `.env`, токены, OAuth secrets, SMTP password, логи, backups и uploads;
- не трогать `connections.json` без отдельного плана;
- не отключать preview-only;
- не включать реальные write-действия в рекламных кабинетах;
- не открывать `/mcp` без авторизации;
- не смешивать рекламные кабинеты разных пользователей.

## Как запустить локально

На этом проекте лучше использовать Docker/sandbox-режим, чтобы агент видел только рабочую папку, а не весь компьютер.

### 1. Установить зависимости

На Windows рекомендуемый путь:

1. Установить WSL 2.
2. Установить Ubuntu для WSL.
3. Установить Docker Desktop.
4. В Docker Desktop включить WSL 2 backend и интеграцию с Ubuntu.
5. Убедиться, что `docker --version` работает в Ubuntu/WSL.

Node.js тоже нужен для Agent Canvas. Нужна версия Node.js 22.12 или выше.

### 2. Запустить OpenHands Agent Canvas

Вариант без Docker проще, но менее безопасен: агент получает доступ к файловой системе машины. Для HolyMedia MCP предпочтителен Docker/sandbox.

После запуска открыть:

```text
http://localhost:8000
```

В интерфейсе выбрать проект HolyMedia MCP и дать агенту задачу.

## Какую задачу давать OpenHands

Хороший пример:

```text
Проверь модуль AI-анализа сайта. Не трогай секреты и деплой. Исправь дубли в отчете, добавь тесты и запусти pytest, compileall, node --check и git diff --check.
```

Плохой пример:

```text
Сделай все и задеплой.
```

Лучше давать агенту конкретный участок работы, проверяемый результат и список запретов.

## Когда не использовать OpenHands

Не стоит давать OpenHands:

- прямой доступ к live-секретам;
- задачу менять production env без контроля;
- задачу включить live writes в рекламных кабинетах;
- задачу массово рефакторить проект без необходимости;
- доступ к VPS без явного решения команды.

## Проверки после работы агента

После любых изменений нужно запустить:

```powershell
pytest -q
python -m compileall src scripts
node --check src/ad_mcp/web/static/app.js
git diff --check
```

Для live-проверки:

```powershell
curl -i https://mcp.holymedia.kz/health
curl -i https://mcp.holymedia.kz/ready
curl -i https://mcp.holymedia.kz/mcp
```

Ожидаемо:

- `/health` возвращает `200`;
- `/ready` возвращает `200`;
- `/mcp` без token возвращает `401`.
