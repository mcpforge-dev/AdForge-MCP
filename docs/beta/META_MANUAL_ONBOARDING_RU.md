# Ручное подключение Meta через специалиста HolyMedia

Пока приложение Meta проходит App Review, публичная кнопка OAuth в кабинете клиента отключена. Вместо неё клиент оставляет заявку. Заявка привязана к его user/workspace и содержит только безопасные идентификаторы рекламных объектов.

## Что клиент указывает

- название компании или проекта;
- ID рекламного кабинета Meta, например `1423247033195473` или `act_1423247033195473`;
- Business Portfolio ID, если он известен;
- Facebook Page ID и Instagram username, если нужны для отчётов;
- удобный канал связи и короткий комментарий.

Email берётся из аккаунта HolyMedia. Пароль Meta, access token, Page Access Token, app secret, client secret и коды подтверждения никогда не запрашиваются и не принимаются формой.

## Что делает специалист

1. Открывает заявку в `/admin` и проверяет, что клиент имеет право подключать указанный рекламный кабинет.
2. Просит клиента выдать HolyMedia или уполномоченной PPC-компании доступ к нужному рекламному активу через Meta Business Settings → Partners / Рекламные аккаунты. Пароль клиент не передаёт.
3. Проверяет доступ специалиста к рекламному кабинету, Business Portfolio и, если заявлены, Page.
4. Нажимает `Подключить Meta` в строке заявки. Admin-only OAuth подписан ID заявки, user и workspace клиента. После возврата специалист подтверждает только рекламный аккаунт из заявки. Токен остаётся в закрытом server-side storage и не попадает клиенту, в чат или в отчёт.
   Для ручного клиентского сценария запрашиваются только `ads_read`, `business_management`, `pages_show_list` и `pages_read_engagement`; `ads_management` не добавляется даже при включённом отдельном App Review тесте write-workflow.
5. Проверяет workspace клиента, account ID и read-запросы Meta. Рабочие write-действия остаются запрещены глобальным `AD_MCP_PREVIEW_ONLY=true`.
6. Обновляет статус заявки: `В работе` → `Готова к подключению` → `Завершена`, оставляя клиенту только понятную заметку.

## Важное ограничение текущего этапа

Форма заявки и админский трекинг не дают специалисту права на рекламный кабинет автоматически. Реальное подключение выполняется только после выдачи доступа в Meta Business Manager и отдельной проверки привязки credentials к workspace клиента. Нельзя решать задачу передачей персонального access token клиента.

## Включение публичного OAuth после App Review

После подтверждения Meta и проверки permissions установите:

```dotenv
AD_MCP_META_MANUAL_ONBOARDING_ENABLED=false
```

Перезапустите только web/http services и проверьте OAuth callback. До этого ручная заявка остаётся основным клиентским сценарием.
