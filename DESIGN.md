# Design

Визуальная система HolyMedia MCP: текущее состояние + зафиксированное направление редизайна. Все команды дизайна читают этот файл вместе с PRODUCT.md перед работой.

## Confirmed Decisions (2026-07-16)

1. **Тема:** только тёмная; без переключателя. Должна хорошо читаться днём.
2. **Акцент:** сохраняем `#7c9aff`, но ≤ 10% интерфейса; основная палитра — спокойные нейтральные тёмные; красный/зелёный/жёлтый — только реальные статусы и ошибки.
3. **Типографика:** Manrope (с кириллицей), одно семейство, чёткая шкала для заголовков/текста/подписей/таблиц.
4. **Приоритет поверхностей:** (1) landing, шапка/навигация, вход/регистрация/pop-up'ы, dashboard shell → (2) Начало работы, Подключения, MCP, SEO, Анализ сайта, Профиль → (3) скачиваемые отчёты, admin, mobile + accessibility polish.
5. **Landing и кабинет** — одна дизайн-система; landing чуть выразительнее, но без отдельного визуального мира и AI-градиентов.
6. **Скачиваемые отчёты** (SEO, AI-аудит) входят в объём: профессиональные клиентские документы HolyMedia.
7. **Admin** наследует сетку/типографику/формы/кнопки/токены; глубокий редизайн — после клиентских экранов.
8. **Язык:** русский; компоненты и сетка готовы к более длинным текстам (EN/KZ в будущем).
9. **Бренд:** текущий знак HolyMedia MCP сохраняется; новый логотип/фирстиль не придумывать без согласования.

## Design Direction

Спокойный профессиональный B2B SaaS. Интерфейс должен выглядеть как продукт digital-агентства — аккуратный, взрослый, премиальный, — а не как серверная админка и не как «нейросеточный» AI-стартап.

Опорные качества:

- **Человеческий, не технический.** Слова, состояния и подсказки написаны для маркетолога; никакого жаргона протоколов в клиентских экранах.
- **Минимум плашек и ярких цветов.** Цвет несёт смысл (статус, действие), а не декорацию. По умолчанию — Restrained-стратегия: нейтральные поверхности + один акцент.
- **Без кислотных градиентов.** Никаких фиолетово-розовых AI-градиентов, glow-эффектов и gradient-text.
- **Без карточек внутри карточек.** Вложенные карточки запрещены; секции строятся сеткой, отступами и типографикой.
- **Сильная сетка и типографика.** Иерархия достигается размером, весом и ритмом, а не рамками и заливками.
- **Понятные состояния и действия.** У каждого экрана одно главное действие; каждый интерактивный элемент имеет default / hover / focus / active / disabled / loading / error; загрузка — skeleton, а не спиннер в центре контента; пустые состояния учат интерфейсу.
- **Тёмная тема остаётся**, но спокойная и премиальная: глубокие нейтральные поверхности, мягкие границы, сдержанный акцент.
- **Mobile и accessibility обязательны:** контраст ≥ 4.5:1, фокус-стили, reduced motion, тач-цели ≥ 44px, адаптивные таблицы и формы.

Паттерны текущего UI, которые редизайн пересматривает:

- Логотип-точка с градиентом `--accent → #9f7cff` (единственный градиент; допустимо оставить или упростить).
- Много бейджей и chips (`badge--ok/warn/err/info/muted`, `chip--beta`) — сократить и приглушить.
- Карточки (`card`) как основная единица вёрстки, местами с вложенными `setup-card` внутри `card` — устранить вложенность.
- Кнопки четырёх видов (primary / secondary / ghost / danger) — вокабуляр нормальный, следить за «одним главным действием» на экран.
- Типографика: базовый размер 15px, заголовки weight 600, letter-spacing −0.01em; шкала не формализована — задать явную rem-шкалу с шагом 1.125–1.2.

## Color

- Пространство — OKLCH для новых значений; текущие hex-токены конвертируются по мере редизайна.
- Стратегия — **Restrained**: тёмные нейтральные поверхности (с лёгким тонированием ≤ 0.015 chroma в сторону фирменного оттенка), один акцент ≤ 10% поверхности.
- Акцент используется только для: primary-действий, текущего выбора (активная вкладка), индикаторов состояния. Не для декора.
- Семантические статусы (ok / warn / err / info) — приглушённые: тонированный фон низкой насыщенности + читаемый текст; никаких неоново-ярких score-бейджей.
- Score и метрики отображаются типографикой (цифра + подпись + сдержанный индикатор), а не гигантскими цветными плашками.
- Вторая нейтральная поверхность для панелей/тулбаров допустима (чуть светлее или темнее контентной), без рамок «карточка в карточке».
- Контраст обязателен: body-текст ≥ 4.5:1, крупный ≥ 3:1, placeholder ≥ 4.5:1. `--text-faint` в текущей палитре — первый кандидат на проверку и осветление.

## Typography

- Одно семейство на весь продукт (системный стек или один хорошо настроенный sans, например Inter); без пар шрифтов и display-шрифтов в UI.
- Фиксированная rem-шкала с шагом 1.125–1.2 (не fluid/clamp): caption, body, h4, h3, h2, h1 — явные токены.
- Заголовки: weight 600, letter-spacing не туже −0.04em; `text-wrap: balance` на h1–h3.
- Прозаические блоки (подсказки, отчёты) — line length 65–75ch; таблицы данных могут быть плотнее.
- Моно-шрифт только для реально технических значений (MCP URL, ключи, примеры запросов) — не для акцентов.

## Layout

- Сильная сетка: единая максимальная ширина shell (сейчас 1280px), последовательные вертикальные ритмы секций, выравнивание по колонкам.
- Карточка — не единица вёрстки по умолчанию. Секции строятся заголовком, отступами и сеткой; карточка появляется, когда есть реальная граница сущности (платформа в «Подключениях», отчёт в истории).
- Вложенные карточки запрещены. Текущие `setup-card` внутри `mcp-card` перестраиваются в плоские секции с подзаголовками.
- Flexbox для одномерных раскладок, Grid для двумерных; адаптивные сетки через `repeat(auto-fit, minmax(280px, 1fr))`.
- Семантическая шкала z-index (dropdown → sticky → modal-backdrop → modal → toast); не 999/9999.
- Responsive — структурный: вкладки и таблицы перестраиваются на mobile, а не масштабируются.

## Components

- Единый вокабуляр компонентов на все экраны (кабинет, admin, landing): одна форма кнопок, одни поля, один стиль иконок.
- Каждый интерактивный компонент: default, hover, focus-visible, active, disabled, loading, error.
- Загрузка — skeleton-состояния по форме будущего контента; «Загружаем...» с пустым блоком заменяется.
- Пустые состояния объясняют следующее действие («Подключите первую платформу»), а не констатируют пустоту.
- Статусы подключений/диагностики: текст + сдержанный индикатор; не полагаться на цвет как единственный носитель смысла.
- Модалки — только там, где они уже оправданы (auth, выбор аккаунтов после OAuth); новые сценарии сначала пробуют inline-решение.
- Формы (анализ сайта, auth, профиль): ясные лейблы, видимые ошибки рядом с полем, понятная валидация.

## Motion

- 150–250 ms, ease-out (quart/expo); без bounce и elastic.
- Motion передаёт состояние (переключение вкладки, появление toast, раскрытие панели), не украшает.
- Никаких orchestrated page-load анимаций в кабинете; прогресс длинных операций (сбор отчёта) — честный статус, а не театр.
- `@media (prefers-reduced-motion: reduce)` — обязательная альтернатива (crossfade или мгновенно) для каждой анимации.

## Anti-patterns (запрещено в этом продукте)

1. Чрезмерно яркие score-бейджи и неоновые статус-плашки.
2. Россыпь разноцветных chips в одном экране.
3. Типичные AI SaaS-градиенты (фиолетово-розовые, кислотные), gradient-text, glow.
4. Перегруженные карточки и карточки внутри карточек без необходимости.
5. Слишком много равнозначных кнопок; ряд из primary-кнопок.
6. Технические термины в клиентском интерфейсе (endpoint, transport, payload, token — вне раздела для разработчиков).
7. Шаблонные тексты и канцелярит («данный сервис осуществляет...»); пишем коротко и по-человечески.
8. Визуальный шум вместо иерархии: рамки, заливки и бейджи там, где хватает типографики и отступов.
9. Side-stripe borders (цветная полоса слева на карточке/алерте) как акцент.
10. Hero-metric шаблон: огромная цифра + мелкая подпись + градиентный акцент.

## Scope Notes

- Клиентские поверхности (landing, кабинет, отчёты) — приоритет; admin-панель наследует систему, но не диктует её.
- SEO-отчёты и AI-аудит сайта — «лицо агентства»: их вёрстка и скачиваемые документы должны выдерживать показ клиенту.
- Тексты интерфейса — часть дизайн-системы: тон спокойный, конкретный, без обещаний «магии».
